## 8. Pitfalls learned
- Generic from earlier chats: `check_design.py` prefix→owner map (keep `repo:` in `app-meta.js` accurate — it is `'tickler'` here); old-style service workers wiped sibling caches; brand-tagline media rule must come after `.brand__sub`; guard `classList` changes inside the body MutationObserver; alias tokens rather than importing starter component CSS into older apps; Companion apps now default to match-device.
- Batch Tickler: never reuse `.today__q` for a new Home card — `today_test.py` reads the first one (QOTW uses `.qotw-q`). Radio defaults: an unset choice must start unchecked (the truths form once pre-checked statement 1). Buttons rendered by a view need their listeners wired in `AFTER.<view>` (the sort buttons were missed once); the starter's `main` click handler only covers the search-page filters. A view that re-renders on every keystroke must restore focus/caret (see `AFTER.batch`). The home hero gradient over a photo banner must start transparent for the top third or it tints the picture. Badge toasts appear on first load of a seeded test (collector, met everyone…); harmless, but they can cover elements in screenshots. After saving My card the app redirects to `#/person/<id>` a moment later — wait for that hash before navigating elsewhere in tests. In Playwright, fields inside closed `<details>` can't be filled — open them first (`document.querySelectorAll('details.fgroup').forEach(d=>d.open=true)`); the regression script on `dev-tools` does this. `.guess__ask` is uppercase via CSS, so text assertions must be case-insensitive (same for `.today__k`). Text-only QR: ~2.2 KB JSON scans reliably from a phone screenshot; photos never go in the QR. The `qa/batch.json` fixture has no playlists — `today_test.py` seeds its own cards via localStorage `bt:v1:batch`.
- Repo push access is granted per repo per session via `add_repo` (worked first time for `tickler`); `gh api repos/…/pages` is blocked by the proxy, but `gh api repos/…/actions/runs`, `…/deployments` and `…/actions/runs/<id>/rerun-failed-jobs` work.
- **GitHub Pages deploy can silently fail**: on 6 Nov the 1.9.0 run's build succeeded but the deploy step timed out after 10 min (`updating_pages`), the 1.8.0 run was cancelled by the newer push, and the live site stayed on 1.7.1 for 8 hours until she noticed. "Re-run failed jobs" sat in GitHub's queue for 30+ min; an **empty commit to main** built and deployed in under a minute. After every push, check `gh api "repos/isaymotion/tickler/actions/runs?per_page=1" --jq '.workflow_runs[0] | "\(.head_sha[0:7]) \(.status) \(.conclusion)"'` shows `completed success` for the new sha (1.10.0–1.16.0 each took ~2 min). Pushing many releases minutes apart cancels the in-between runs (fine) — just verify the last one. The live site can't be fetched from the sandbox (curl → 000), so the Actions API is the only check.
- The run can show `in_progress` for ~5 min after every job finished (seen on 1.17.0). Before treating it as stuck, check `gh api repos/isaymotion/tickler/actions/runs/<id>/jobs --jq '.jobs[]|"\(.name) \(.status) \(.conclusion)"'` — if `deploy completed success`, it's live.
- Her phone updates itself: sw.js is network-first with skipWaiting + clients.claim, so a close-and-reopen (twice at most) picks up a deployed version; "still old" means the deploy didn't happen, not a caching bug.
- `make_icons.py` needs `cairosvg` for SVG sources (`pip install --break-system-packages cairosvg`); PNG sources work without it. For a photo/pixel icon with white corners, flood-fill the corners to transparent first.
